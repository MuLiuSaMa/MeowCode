四、每个项目的优缺点

🥇 codex-main Rust · OpenAI · 208 万行

工业级标杆。21,229 测试 + deny unwrap 40+ 项 + 多平台 CI

✓ 优点

  • 架构分层彻底（186 crate，Session/Turn/Step 三级上下文）
  • 质量门禁业界顶配，非测试代码几乎零 unwrap
  • Token 效率全链路系统化（7 项手段互相咬合）
  • 安全体系深入（landlock/seatbelt/Windows sandbox）
  • 压缩机制最全（本地/远程/token-budget 三实现）

✗ 缺点

  • 208 万行认知成本极高，feature flag 膨胀
  • 强绑定 OpenAI（仅 Responses wire，无 Anthropic）
  • 已知问题未清：TRACE 日志磨损 SSD(#28224 未修)、V8 macOS 崩溃、Guardian 误报
  • 文档严重脱节（config.md 6 行 stub）

🥈 opencode-2 TS · 85 万行

现代架构。Effect-TS + 持久化事件 session + 226 provider / 8,443 模型

✓ 优点

  • 事件溯源 + 写前 claim，崩溃可恢复
  • provider/协议层自研且深（36+ 协议适配、4 breakpoint 缓存）
  • 1,159 测试文件 + 自定义 lint 规则
  • 产品形态完整（TUI + Electron + Web + ACP）

✗ 缺点

  • 85 万行，session 单目录 38 文件，上手成本高
  • 强绑定 Effect 4.0 beta + bun，选型激进排他
  • v2 剧烈演进：HTTP API 139 端点仍在审计收敛
  • provider 拼通过度碎片化，长尾行为靠白名单兜底

🥉 ZCode-main TS · 智谱 · 205 万行

测试超过源码。显式 turn 状态机 + 架构检查 0 violations

✓ 优点

  • core 测试 13 万行 > 源码 10.4 万行
  • turn 状态机非法迁移即报错、工具调度器拓扑+并行
  • 治理工具体系（knip + architecture-check + pre-push）
  • provider 抽象干净（三协议 + revision 热更新）

✗ 缺点

  • 内部审计顽疾：fix:feat ≈ 3.7:1、CI job 曾被禁用、max-lines 被 162 文件绕过
  • 69 文件持有模型选择状态副本、logger 5 套并存
  • 强绑定智谱（Coding Plan 网关自动转发无逐次确认）
  • 无 OS 沙箱（NOTICE 自述不提供默认沙箱）

4 · metis-main TS · src 9 万行 + 测试 7.4 万

Token 效率工程化最深。310 测试文件，真实 TODO 为 0

✓ 优点

  • Prompt 预算写成 CI 回归测试，膨胀直接被拦
  • 缓存前缀字节级不变量断言
  • 54 provider + OAuth 订阅登录
  • steering 插入、并行/顺序双模式、热切换模型

✗ 缺点

  • 核心三包只发 dist 无源码，调试必须回上游 pi
  • 巨型文件（interactive-mode 6,555 行）
  • 概念膨胀（T0–T3 + G1–G7 + self-learning）
  • desktop UI 细节测试约 60 文件，维护不成比例

5 · deepseek-harness TS · DeepSeek · 4.8 万行

架构最现代。everything-is-a-plugin + Cordis，1,497 spec

✓ 优点

  • 插件化彻底，55 个包职责单一
  • PTC run_code（模型写代码编排工具）
  • compaction 子包齐全（pruner / image-offload）
  • 多端（cli/desktop/web/acp）+ 插件市场

✗ 缺点

  • developer preview，明示破坏性变更
  • 概念多（plugin/surface/node/epoch），调试路径长
  • 沙箱/权限体系文档化程度低
  • 快照/评测产物目录留在仓库

6 · MeowCode（本项目） TS · 2.1 万行

七者最小核心。474 测试全过 + tsc 零错误 + 0 TODO

✓ 优点

  • 1/100 代码量保持一线卫生水平（对比 codex）
  • Token 核心单项齐：三点缓存+降级重试、双层压缩、usage 锚点、三层触发链
  • CJK 感知估算 + 国内服务商目录，差异化
  • 写后验证闭环（verify.ts）七者中少有的
  • 审批细节（diff 外部刷新、子 Agent 审批记父会话）

✗ 缺点

  • 无 MCP / 无沙箱 / 无 LSP / 无分支 / 无 checkpoint（6 个参考项目全支持 MCP）
  • token 效率系统性排第 7（提示词未分区、无免费剪枝层、无 code mode）
  • runtime.ts 单文件 3,294 行
  • AGENTS.md 单层读取；辅助请求无缓存亲和；无 CI/未初始化 git

7 · AllAgent.NET C# · 2.78 万行

工程质量极高。0 TODO + 448 测试（含真实 microVM）

✓ 优点

  • CodeAct 范式优雅（模型只见 execute_code + Hyperlight 隔离）
  • prompt 缓存有字节级回归测试
  • 安全深入（路径边界、SHA256 审计、孤儿消息修补）
  • Roslyn 源码生成器消灭工具样板代码

✗ 缺点

  • 平台深锁定：Windows x64 + Hyperlight + PowerShell 7.6，跨平台不可行
  • Hyperlight 1.24 preview 依赖风险
  • AgentEngine 单方法 ~300 行塞十余职责
  • Web 端 1.27 万行 TS 仅 3 个测试文件
